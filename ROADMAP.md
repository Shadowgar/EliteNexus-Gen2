# Praetorium roadmap

All systems. One command.

Current development baseline: 0.1.0-alpha.1. The independent source is integrated, not fully verified or released. The goal is a context-aware shipboard command platform, not a clone of every specialist tool. No dates or version promises are assigned to unfinished capabilities.

| Order | Outcome |
| --- | --- |
| 1 | Lean development workflow; one small local acceptance assignment to establish the new token and Windows build baseline. |
| 2 | Correct inherited gameplay data and reliability defects, one bounded change at a time. |
| 3 | Native OpenAI integration and a useful read-only context-aware assistant; preserve credential and service authorization boundaries. |
| 4 | Connected trading, carrier logistics, navigation, exploration and exobiology decisions. |
| 5 | Persistent objectives and contextual memory with explicit user control. |
| 6 | VoiceAttack interoperability and conversational command handling; no unattended gameplay automation. |
| 7 | Desktop command UI, tablet/secondary display and VR, prioritized by actual gameplay needs. |

Performance, accessibility, privacy, licensing and data integrity apply throughout. Evaluate supported community APIs and compatible integrations as needed; no broad repeated ecosystem audit. Scope and priority may change with owner direction. Production service access, signing and publication require separate approval.

Use [BACKLOG.md](BACKLOG.md) for active work and [AGENTS.md](AGENTS.md) for how to work. The [improvement register](docs/GEN2_IMPROVEMENTS.md) holds completed evidence, not a mandatory reading list. Earlier research and decisions remain historical references; this roadmap is the working sequence, not a claim that all requirements are implemented.
